Safe troubleshooting

Read the exact status first. These steps do not authorize actions or unlock protected recovery.

Install or doctor reports a problem

Check the Node/npm compatibility displayed by mecord-connect doctor and compare the installed package version with the source you intend to run. Keep the last-good installation. Do not reinstall or delete the state folder just to clear an error.

Agent already running or another instance owns the lock

Inspect the current Mecord console and device status. Reuse the existing authorized instance rather than starting a second one. Never kill an unknown process or remove an ownership lock to bypass another active session.

Locked, blocked or uncertain recovery

Open Recovery and read the exact affected action and side-effect disposition. Uncertain writes are not retryable by assumption. Keep original receipts quarantined, use only the listed owner-approved reconciliation path, and do not delete or replay records.

Pairing or local browser sign-in fails

Confirm the intended device is online. Request a fresh one-time Control Center sign-in code from its local Mecord console. The browser session only opens the dashboard; it does not grant native action approval, device pairing or recovery rights. Never share bearer tokens.

Device is offline or relay is disconnected

Check that the device and relay status are current and that the local agent is running. Restore network access and re-check the reported generation before reconnecting. Avoid wiping local journals or replaying outstanding side effects.

Approval expired or timed out

Read the action, exact target and current status in Approvals. An expired grant is not permission to continue. Request fresh approval through the trusted native authority and verify scope again. Browser sign-in alone never approves an action.
